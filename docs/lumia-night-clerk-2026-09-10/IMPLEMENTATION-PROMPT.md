# 루미아 문서국 — 승인된 야간 기록관 UI 재구현 프롬프트

## 작업 목표와 우선순위

기존 er-apps 정적 HTML 서비스를, 이 폴더의 승인된 `preview.html`과 같은 야간 접수 로비로 재구현하라. 이 문서는 이후 구현 작업을 위한 명세이며 이번 자료 전달에서 앱 구현이나 배포를 실행하라는 명령이 아니다. 실제 구현을 요청받은 시점에 적용하라.

사용자가 승인한 외형을 임의로 새 디자인으로 바꾸지 말 것. 시각적 기준은 `approved-original.fragment.html`, 비교용 실행본은 `preview.html`, 이미지 원본은 `assets/night-clerk-original.png`, 실제 시안 표시 이미지는 `assets/lumia-art.jpg`이다. 이미지에 얼굴을 새로 그리거나 캐릭터·의상·표정을 교체하지 말 것. 디자인 설명보다 원본 CSS/DOM의 정확한 수치가 우선한다. 기능은 기존 서비스의 실제 데이터 계약을 우선하며, 모형의 단일 닉네임 폼으로 실제 각 문서의 입력을 축소하지 말 것.

## 확정 컨셉

은발 냉미녀가 지키는 야간 기록실. 피곤하고 귀찮지만 요청받으면 묵묵히 일을 처리한다. 캐릭터가 감성의 중심이며 UI는 조용한 접수대다. 입장 대사: “하… 또 왔네.\n이번엔 무슨 서류인데?” 보조: “필요한 것만 골라. 오래 걸리니까.” 귀찮음은 짧은 말투와 타이밍으로 표현한다. 욕설, 모욕, 과한 츤데레 감탄사, 친절한 AI 안내문, 수다스러운 튜토리얼을 덧붙이지 않는다. 시스템 오류와 입력 안내는 정중하고 명확한 문장으로 별도 제공한다.

카드 그리드, 네온, 보라 그라디언트, 밝은 노란 출격 버튼, 과장된 SF HUD, 장식용 수치·온라인 카운터, 무의미한 영문 표어, 유리 카드와 과한 둥근 모서리를 추가하지 않는다. 작은 LUMIA ARCHIVES 로고 이외에 영어를 장식적으로 늘리지 않는다.

## 시각 수치

- 배경 #0c161c, 글자 #e5eae9, 본문 #b6c6c6, 보조 #91a9aa. CTA 배경 #cfdbd3 / 글자 #172726. 오류 #e4ae9d. 테두리 #c1d2d026 ~ #c1d2d033의 1px 선.
- Noto Sans KR 400/500/600/700. 일반 13px/1.7, 헤딩 22px/1.4 weight500, 대사23px/1.7 weight400 letter-spacing -1px, 메뉴15px weight400. 작은 문서번호만 monospace 10px. 원본 9~11px 보조텍스트는 실제 1:1 스케일에서 읽기 검증하여 기능성 안내를 너무 작게 유지하지 말 것.
- 헤더 padding25px 35px. 데스크톱 main grid: `minmax(0,1fr) 310px`, gap28px, padding13px 35px 32px, min-height588px. 전체 서류에서는 오른쪽475px. 오른쪽 패널의 배경은 #0c171e, opacity .96, 본문 영역에만 덮인다.
- 원화는 이미 배경과 인물이 합쳐진 단일 이미지다. object-fit cover, object-position42% top, 변형 중심35% 35%. 원본의 오른쪽·하단 그라디언트 veil을 정확히 유지해 얼굴과 글자의 대비를 확보한다. 캐릭터를 임의로 분리하거나 배경 blur 처리하지 않는다.
- 목록은 투명 배경과 가로 구분선. 전체 목록 row min-height65px, 제목14px, 보조10px(모바일11px), 수평 여백 최소. 모서리는 각진 형태.
- standalone의 max-width1200px와 min-height100vh는 미리보기 문서용 wrapper다. fragment 내부 수치와 구분하고, 실제 서비스의 큰 화면에서 전체 브라우저 높이가 불필요한 검은 공간만 만들지 않는지 확인한다.

## 확장 가능한 모델과 상태

단일 문서 레지스트리의 각 항목에 stable id, name, category, short, description, target, href, inputSchema, status, dialogue를 둔다. 표시 번호와 전체 개수·분류·검색·최근 목록은 여기서 파생한다. stable id를 배열 index로 대신하지 않는다. 신규 문서 하나를 등록하면 홈 개수, 검색, 분류, pagination에 자동 반영되어야 한다. 비활성 문서는 disabled 이유를 보여주고 실행되지 않는다.

홈→전체 목록→문서 상세→접수 중→실제 결과/오류의 상태를 명시적으로 관리한다. 홈은 최근 선택3개, 비어 있으면 death/fault/payroll 바로 찾기를 사용한다. 1개만 사용했을 때 가짜로 나머지를 최근으로 표시하지 않는다. 목록은 이름·분류·설명으로 공백 무시 검색, 분류 필터, 6개씩 pagination. 필터/검색 변경 시 1페이지로, 마지막 항목 삭제 시 유효 페이지로 보정. 문서가 6/7/30/100개일 때 모두 동작하도록 한다. 실제 서비스를 확인하기 위해 플레이어 데이터를 무단으로 대량 조회하지 말고, UI 시험용 등록 데이터로 검증한다.

상세에서 뒤로 가면 출발 화면 및 목록의 query/category/page를 복원한다. 홈으로 돌아와도 입력 닉네임 유지. 실제 구현에서는 버전 키를 둔 localStorage 또는 sessionStorage로 최근 stable ids 및 닉네임을 저장하고, 스토리지 거부/손상/삭제된 id를 안전 처리한다. 자동 조회는 실행하지 않는다. 공유 URL에 닉네임이 포함될 경우 URL encode 및 기존 앱 계약을 지킨다. 브라우저 뒤로가기와 내부 뒤로가기가 일치하도록 구현한다.

시안은 한 닉네임만 받지만 실제 서비스 입력은 보존해야 한다. 자격증=닉네임/실험체/스킨/양식2종. 과실=본인/팀원1 필수, 팀원2 선택/시즌/모드/40·60·100판. 원수=내 닉네임에서 후보 찾기와 원수 닉네임 직접 입력. 급여=10·20·30판. 기타 기존 폼·선택값도 실제 코드에서 확인하라. 모든 페이지에 공통 홈 복귀와 사용자 맥락 보존을 제공한다.

## 애니메이션 — 원본과 동일하게 시작

| 동작 | 수치 |

| 패널 폭·원화 이동 | 380ms, cubic-bezier(.22,.7,.2,1) |
| 전체 목록의 원화 | translateX(-38px) scale(1.025) |
| 패널 내용 진입 | x18px→0, opacity .1→1, 320ms |

| 접수 모형 | 진행선850ms, 완료900ms, 완료영역 y12px→0/250ms |

실제 API 연결에서는 마지막 행의 가짜900ms 완료를 제거한다. 네트워크 응답 전 성공 화면을 보이지 않는다. 실제 단계가 없으면 '기록 확인 중'의 비정량 상태만 표시하며 가짜 백분율을 쓰지 않는다. 중복 제출 방지, 요청 취소/화면 이동 후 늦은 응답 무시, 재시도, 타임아웃, 부분성공을 처리한다. 시스템 글을 지연해서 타이핑하지 않는다. 루프 파티클, 화면 흔들림, 모든 요소의 둥둥 떠다니기는 금지한다.

## 캐릭터 대사

원본 documents 배열의 quote/aside를 정확히 가져온다. 대표 대사: 자격증 “자격증? …응. 잘한다는 말로는 부족했나 보네.” / 사망 “또 죽었어? …알았어. 어디서 죽었는데.” / 과실 “이번에도 네 잘못은 아니라는 거지?” / 원수 “아직도 그 사람 찾고 있어? …이름 줘 봐.” / 신용 “그 실험체, 또 하려고? …기록부터 보고 결정해.” / 급여 “이만큼 했는데 오히려 깎였다고?” 전체 목록 “...그거 말고? 목록 줄 테니까 직접 찾아.” 실제 줄바꿈·말줄임표는 원본 값을 따른다. 긴 사용자 닉네임은 textContent로 넣으며 HTML로 해석하지 않는다.

## 반응형과 접근성

721~860px는 기본 패널285px, 전체390px, 좌우25px, gap20px, 대사20px. 720px 이하는 단일 열, 좌우24px, 위쪽 캐릭터영역 min-height370px, 원화 height650px/object-position35% top, 아래 접수대. 모바일 목록 전환 원화 x-8px/scale1.015. 모바일 세로 공간이 길어지는 원본 특성을 확인하고, 문서 선택 후 해당 입력/패널로 자연스럽게 접근되도록 하되 얼굴을 완전히 감추지 않는다. 360/390/720/860/1200/1440px 및200% 확대 확인. 가로 overflow 금지.

button/input/label을 의미에 맞게 사용. hidden 패널은 Tab 접근 불가. 화면 전환 시 새 제목 또는 적절한 제어로 focus 이동하고, 뒤로 가면 시작 버튼으로 복귀. Escape는 상세→목록 또는 홈, 목록→홈. 검색/분류 aria-pressed와 결과 수 role=status. 대사 시각 타이핑은 aria-hidden, 완성된 대사 하나만 live 영역에 넣어 글자마다 읽지 않게 한다. focus-visible2px outline 및 충분한 대비. 모바일 클릭 영역44px 이상. prefers-reduced-motion 시 CSS/WAAPI/타이핑을 모두 중단하고 완성 상태 즉시 표시. 실행 중 모션 설정 변경도 처리. 입력 오류를 캐릭터 대사만으로 전달하지 말고 해당 필드의 텍스트·aria-invalid·aria-describedby로 표시한다.

## 자료의 한계와 구현 검증

승인 fragment는 디자인 모형이다: 모든 url:null, API 요청 없음, 실제 발급 없음, 최근 목록은 JS 메모리뿐, 닉네임은 현재 input DOM에만 남으며 새로고침하면 사라진다. PNG/PDF 저장·실제 결과·query URL 연결도 모형에 없다. 원본은 Tweak가 존재할 때만 선택적으로 패널 속도 컨트롤을 추가한다. 배포본에는 Tweak 관련 분기를 제거한다. Google Fonts @import 네트워크 의존이 있으며 실패하면 sans-serif fallback으로 폭이 바뀐다. 외부 폰트를 차단하는 환경이면 적법한 폰트 파일과 라이선스를 확보해 self-host하되 이번 자료에는 미포함이다. 이미지 파일은 제공된 자산으로 동일 외형을 재현할 수 있다.

작업 전 AGENTS.md와 기존 코드/빌드/검증 지침을 읽는다. 별도 종량제 API 호출은 사용자 명시 승인 없이 사용하지 않는다. 이미지 원본을 다시 생성할 필요 없다. 기존 앱의 실제 기능·유머 산정 로직·고지·데이터 출처·조회 제한을 보존한다. 구현 후 홈/카탈로그/상세/제출/오류/모바일과 결과 저장을 실제 렌더로 검증하고, 기존 check/smoke 중 변경에 맞는 것을 실행한다. 읽기/출력 때문에 비용이 발생하는 검증은 먼저 범위를 확인한다. 배포는 별도 작업 요청의 범위에 따른다. 완료 보고는 변경 파일, 검증, 미연결 항목을 명확히 한다. 기존 코드가 연결되지 않았는데 완료라고 쓰지 않는다.


## 문서별 구현 자료 — 반드시 함께 읽기

`DOCUMENT-UIUX-SPEC.md`를 읽고 `document-studio.html`(원본 `document-studio.fragment.html`)의 6문서 접수/결과 토글을 확인하라. 이 자료는 홈의 확정된 기록관 외형을 각 기능에 확장하는 상세 설계다. 홈 외형의 최우선 기준은 기존 승인 fragment이며, 각 문서는 실제 소스가 가진 입력·판정·데이터 필드·조회 상태·PNG/PDF/공유 링크 기능을 보존하는 범위에서 추가 시안을 적용한다. 예시 수치를 실데이터로 사용하거나 시안의 축약 필드 때문에 기존 기능을 제거하지 않는다. 문서별로 실제 저장 기능 유무를 확인하고, 제안된 신규 저장 기능을 이미 구현되어 있다고 취급하지 않는다. 상황판은 포함하지 않는다. 자료에서 실제 조회·발급이 동작하는 것으로 오인하지 않도록 구현 전후 상태를 구분하라.
