# 야간 기록관 구현 기록 — 2026-09-10

승인 원화와 로비 외형을 정적 서비스에 연결하고, 기존 6개 문서의 입력·조회·판정·결과·저장 기능에 공통 기록관 화면을 적용했다. 자료 폴더의 원본 이미지·승인 시안은 변경하지 않았다.

## 구현 위치

- `hub/index.html`, `hub/lobby.css`, `hub/lobby.js`: 홈, 검색·분류·6개 페이지 목록, 상세, 실제 문서 접수대 연결. 가짜 접수 완료 연출 제거.
- `shared/lumia-documents.js`: 6개 stable ID의 문서 레지스트리, 최근 3개, 버전 있는 닉네임 보존, 차단·손상·읽기 전용 스토리지 대응.
- `shared/night-clerk.js`, `shared/night-clerk.css`: 공통 원화·내비게이션·접수/조회/결과/오류 대사, 키보드·모션 감소·BFCache 복원, 인쇄 제외.
- `er-{cert,death,fault,enemy,credit,payroll}/public/`: 문서별 실제 폼과 결과. 기존 API 공급자와 판정 기준을 유지한다. 누락·부분 실패를 별도로 안내하며 조회 취소 후 늦은 응답이 결과를 덮어쓰지 않는다.
- `build.sh`: 공통 자산과 승인 JPG를 `dist`로 조립. 상황판을 내비에서 제외하고 기존 `/map/` 주소는 `/`으로 안내한다. 지도 소스는 보존했다.

자격증의 실험체·스킨·2양식과 검정 근거, 사망의 경기 선택·사인 인과관계, 과실의 2~3명·조건·경기별 비율과 약관 근거, 원수의 후보·직접 조회·사망 사슬·MMR 추이, 신용의 대장·개별 평가·Thin File, 급여의 10/20/30판·RP 누락 정책을 유지한다. 신용 조회 이력 고지는 실제 구현인 브라우저의 최근 30일 기록으로 명확히 했다.

## 실행과 검증

```bash
./build.sh
node --test test/lumia-*.test.cjs er-payroll/test/*.test.cjs
LUMIA_EXTRA_CHECKS=1 node scripts/check-night-clerk.mjs
python3 -m http.server 8099 --bind 127.0.0.1 --directory dist
```

브라우저 결과는 `.cache/night-clerk/report.json`, 화면 및 실제 생성 PNG/PDF는 같은 폴더에 저장한다. UI 검증은 모든 외부 요청을 가로채는 정적 로컬 서버와 합성 전적만 사용한다. API 서버·환경 키·유료 크레딧을 사용하지 않는다.

통합 브라우저 검증 20개 묶음 통과: 7개 경로, 360/390/720/768/860/1024/1200/1440px, 확대 시 720px 재배치, 검색/빈 목록/100개 문서 확장, 입력 보존·실제 경로 연결·뒤로/앞으로·Escape·결과 포커스, 전체 문서 결과·빈 전적·부분 응답·오류·취소, 자격증/사망/과실/급여 PNG, 사망/과실/신용/급여 인쇄용 PDF. 브라우저 예외와 누락된 로컬 자산 0개.

## 검증 범위와 운영 상태

로비와 문서 이동은 이름을 채워 두고 사용자가 각 접수대에서 신청할 때 조회한다. 기존 공유 URL로 직접 접속할 때의 자동 조회 계약은 유지했다. 운영 API는 기존 인터페이스에 연결되어 있으나 이번 검증에서는 실제 플레이어 조회를 실행하지 않았다. 신용정보는 기존에 이미지 저장 기능이 없었으며 이번에는 개별 평가서 인쇄/PDF를 추가했다.

최초 구현·검증 단계에서는 별도 유료 API 호출, 실제 플레이어 조회, 운영 서버 변경, git push 및 배포를 수행하지 않았다. 후속 배포 요청에 따라 기존 GitHub Pages workflow와 도메인 er.dev-heptivision.com을 사용한다. 기존 사용자 미커밋 작업은 보존했다. 로컬 화면에서는 급여의 `발급 예시 보기`로 외부 전적 조회 없이 결과를 확인할 수 있다.
