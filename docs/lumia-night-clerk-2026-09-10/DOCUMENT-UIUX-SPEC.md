# 루미아 문서국 — 문서별 UI/UX 설계

설계일: 2026-09-10 (한국 시간)
기준 서비스: https://er.dev-heptivision.com/
성격: 현행 기능을 보존하는 디자인·동선 명세. 이 문서는 구현 및 배포 완료를 뜻하지 않는다.
함께 제공하는 `document-studio.html`은 예시 데이터만 사용하는 인터랙티브 설계 시안이다.

## 1. 확정된 방향

사용자가 승인한 캐릭터 이미지를 그대로 사용한다. 새 캐릭터 생성, 얼굴 교체, 배경 재생성은 하지 않는다.
캐릭터는 은발 냉미녀 야간 기록관. 귀찮아하지만 처리는 해준다. 과하게 친절한 상담원, 공격적인 비난, 애교·츤데레 밈 남발은 피한다.

- 첫 방문: “하… 또 왔네. 이번엔 무슨 서류인데?”
- 전체 목록: “…그거 말고? 목록 줄 테니까 직접 찾아.”
- 접수: “…이름 확인했어. 거기 앉아 있어.”
- 완료: “다 됐어. 두고 가지 말고.”
- 오류: “기록이 안 와. 잠깐 뒤에 다시 해.”

말투는 캐릭터 대사에만 적용한다. 실제 버튼, 폼 오류, 상태 안내에는 정확한 기능명을 사용한다. 사용자 닉네임을 HTML로 삽입하지 않는다.

### 반드시 피할 것

형광 네온, 노란 출격 버튼, 가상의 실시간 상태 숫자, 임의 좌표·섹터번호, 과장된 영문 약어, 둥근 카드 6개를 반복하는 구성, 생성 이미지에 구워 넣은 텍스트, 로딩처럼 보이도록 꾸민 가짜 API 진행률.

### 화면 구조

1. 로비: 큰 캐릭터, 짧은 대사, 최근 문서 최대 3개, 전체 문서 열기.
2. 접수: 같은 배경과 접수대. 문서에 필요한 필드만 노출.
3. 결과: 캐릭터 영역을 줄이고 결과 문서가 넓어진다. 분석 결과를 읽을 때 얼굴과 장식이 시선을 경쟁하지 않는다.
4. 저장: 화면용 UI와 별개로 문서 영역만 내보낸다. 내비게이션, 캐릭터 대사, 버튼, 로딩은 저장 이미지에서 제외.

데스크톱 결과는 캐릭터 약 22–27%, 문서 작업영역 73–78%. 모바일은 캐릭터 이미지를 상단 160–200px로 잘라 유지하고 결과를 아래로 쌓는다. 사진 전체를 축소해 얼굴이 작아지는 방식은 금지.

## 2. 공통 디자인·상태 규칙

- 바탕 #0C161C / 접수대 #101D23 / 주 텍스트 #E5EAE9 / 보조 #A6BABC.
- 버튼 #CFDBD3, 글자 #172726. 활성 메뉴는 얇은 2px 표시와 글자 밝기로 구별.
- 구분선 rgba(193,210,208,.18). 장식 테두리를 여러 겹 중첩하지 않는다.
- 폰트는 기존 프로젝트의 한국어 폰트를 우선 활용. 대사는 Noto Sans KR 20–24px, 제목 22–28px, 본문 13–14px, 보조 11–12px. 모바일 입력은 16px 이상.
- 결과 서식은 직선 모서리. 필요할 때만 문서 고유 색을 사용한다: 검시의 탁한 적색, 자격증의 낮은 채도 금속색, 정산의 회녹색 등.
- 결과 수치는 고정폭 숫자. 데이터가 없으면 0이나 낮은 점수를 만들어 채우지 않는다.
- 검색 결과 없음 / 플레이어 없음 / 유효 경기 없음 / 일부 데이터 누락 / 외부 서비스 실패 / 캐시 결과를 구별한다.
- API 재시도는 입력값을 보존한다. 뒤로 가기와 문서 이동에도 닉네임을 보존한다.
- 공개 전적 조회 자체에 필요 없는 확인 팝업을 추가하지 않는다.
- 클라이언트 URL에 닉네임을 전달해야 한다면 기존 공유 규칙을 따르고 encodeURIComponent 적용. 닉네임을 URL/analytics로 불필요하게 확산하지 않는다.
- 기존 URL `/cert/`, `/death/`, `/fault/`, `/enemy/`, `/credit/`, `/payroll/`을 유지한다. 로비 registry에 route, id, category, title, searchKeywords, formSchema, dialogueKey 등록.
- 페이지에 직접 들어와도 홈으로 돌려보내지 않는다. 공통 셸에서 해당 문서를 바로 연다.
- 최근 문서 목록은 완료 결과 데이터가 아니라 문서 ID만 최대 3개 저장. 보존 기간/범위는 앱 정책에 맞춘다. 시안은 메모리에만 유지한다.

### 애니메이션

- 로비↔전체목록: 320–380ms, cubic-bezier(.22,.7,.2,1), 접수대 폭 변경 + 배경 최대 38px 이동.
- 목록: 12px 슬라이드 + 투명도, 항목당 24–28ms 간격, 최대 6행.
- 문서 선택: 240–300ms, 16px 이동. 연타 시 이전 전환을 취소하고 마지막 선택으로 정착.
- 대사: 25ms마다 1–2글자. 스크린리더에는 완성 문장 1회만 알림. 폼 입력 중 반복 재생 금지.
- 발급 완료: 실제 응답 후 문서가 12–20px 위로 올라오며 280ms 정착. 도장이 있으면 완료 때 한 번만 200ms.
- 순위, 과실 비율, 금액은 처음부터 정확한 값으로 표시. 의미 없이 0에서 카운트업하지 않는다.
- prefers-reduced-motion: 모든 공간 이동·타이핑·스탬프 제거. 결과를 즉시 표시. 애니메이션 때문에 동작 완료를 지연하지 않는다.

## 3. 자격증 `/cert/`

### 현행 입력 보존

피검정자 닉네임, 운용 실험체 검색·선택, 아글라이아 연구소/검정원 표준 두 증서 양식.
현재 화면은 전 시즌·랭크/일반/코발트 프로토콜 통합 평가를 설명한다. UI 개편 중 임의로 랭크만으로 축소하지 않는다.

### 접수

- 닉네임 다음에 `운용 실험체` 선택. 미선택 상태에는 단일 `실험체 선택` 버튼.
- 버튼을 누르면 접수대 안에 검색 가능한 초상 목록을 펼친다. 전체 캐릭터 수가 많아도 초기 접수 화면을 수십 개 초상으로 채우지 않는다.
- 선택한 실험체는 초상 48px + 이름 + `변경`으로 요약.
- 양식은 `연구소` / `표준` 두 버튼. 문서 미리보기와 함께 선택하되 추가 API 조회를 발생시키지 않는다.
- 필수 입력이 모두 준비되면 `운용 능력 검정 신청` 활성화. 비활성 사유는 옆에 텍스트로 설명.
- 대사: “자격증? …어느 실험체로.”

### 결과

가로형 자격증을 중심에 둔다. 왼쪽 실험체 초상, 오른쪽 닉네임·자격 등급·평가 범위, 아래 발급 정보. 주변에는 `검정 근거` 접기/펼치기. 자격 서식 자체를 카드형 대시보드로 바꾸지 않는다.
연구소 양식은 얇은 기밀선·연구소장 소견, 표준 양식은 종이색·절제된 직인. 문서 핵심 필드는 동일하게 유지.

- 등급 이외의 상세 점수와 계산식은 기존 평가 데이터를 근거로 표시. 새로운 등급·임계값을 디자인 과정에서 발명하지 않는다.
- 실험체/스킨 이미지 실패 시 이름이 남는 대체 초상. 이미지 지연이 자격 결과를 숨기지 않게 한다.
- 조회 기록 부족은 별도 `자료 부족` 상태. 최하위 등급을 임의로 발급하지 않는다.
- 하단: 이미지 저장, 다른 실험체 검정, 문서국으로.

## 4. 사망진단서 `/death/`

### 현행 입력 보존

닉네임 하나. 최근 전적에서 사망 기록을 찾는다. PNG 저장과 인쇄/PDF 유지.

### 접수와 결과

대사: “또 죽었어? …알았어. 기록 줘 봐.”
검시 접수 후 **세로 진단서**가 나온다. 상단 닉네임/경기 식별 정보, 중앙 `직접 사인 ← 선행 사인`의 명확한 인과 순서, 하단 종합 소견과 발급 표시.
사망 위치 등 실제 응답에 없는 필드는 보이는 칸을 채우려고 추가하지 않는다. 대사는 실제 판정 내용을 대체하지 않는다.

- 기본 결과는 서버가 찾은 사망 기록. 경기 전환은 기존 데이터가 여러 기록을 제공하는 경우에만 추가.
- 생존 경기/사망 기록 없음: `조회 범위에 사망 기록이 없습니다.` 표시. 축하 문구만으로 상태 설명을 생략하지 않는다.
- 결과가 나오기 전 PNG/인쇄 버튼을 숨기거나 비활성화.
- 결과 위 작은 판정 요약, 아래 근거. 선행 사인과 직접 사인을 뒤바꾸지 않는다.
- 저장용은 밝은 종이, 짙은 문자, 적색은 도장과 중요한 사인에 제한. 화면 배경은 계속 어두움.

## 5. 과실비율 산정서 `/fault/`

### 현행 입력 보존

내 닉네임, 팀원 1 필수, 팀원 2 선택, 조회 시즌, 사고 유형(전체/스쿼드/코발트), 최근 40·60·100판. 약관 링크 `/fault/terms.html`.

### 접수

닉네임을 이미 알고 있으면 `본인` 영역은 요약 표시하고 수정 가능하게 한다. 팀원 두 칸을 바로 보여주되 선택 필드를 명확히 표기.
시즌·유형·조회 범위는 `조회 조건` 접기 영역에 두고 현재 선택값을 닫힌 상태에서도 한 줄로 표시. 기본값은 현 서비스와 동일.
대사: “이번에도 네 잘못은 아니라는 거지? …셋 다 볼게.”

### 결과

`동일 경기 확인 → 과실 판정 → 기여 근거` 순서. 가장 위에 경기별 결과 선택, 중앙에 **100%를 나눠 갖는 가로 과실 막대**, 그 아래 플레이어별 수치와 근거 표.

- 비율은 실제 서버 값. 반올림으로 합계가 달라 보이면 서버/현재 규칙을 따르며 원값과 표시 기준을 일관되게 사용.
- 색만으로 플레이어를 구별하지 말고 각 구간에 이름·비율을 표시. 좁은 화면에는 막대 아래 레이블.
- 같은 경기가 없는 상태, 패배 경기가 없는 상태, 팀원 조회 실패를 따로 표시.
- “최대 과실”은 재미용 판정 표현이며 개인정보, 실제 인격, 고의 여부에 대한 판단을 덧붙이지 않는다.
- 산정 기준은 바로 근처의 `판정 근거`에서 열고 약관 링크 유지.
- 이미지 저장 시 선택 경기·참여자·비율·핵심 근거를 함께 저장. 일부만 잘라 오해를 만들지 않는다.

## 6. 원수 관측소 `/enemy/`

### 현행 입력 보존

`내 닉네임으로 색출`과 `상대 닉네임 직접 입력` 두 경로. 기존 공개 기록 조회 의미를 유지한다.

### 접수

기본은 내 닉네임. 아래 텍스트 버튼 `상대 이름을 알고 있어요`로 직접 검색 전환. 비활성 입력은 숨기되 사용자가 쓴 값은 보존.
대사: “아직도 그 사람 찾고 있어? …이름 줘 봐.”

### 결과

종이 증서 대신 **관측 기록 타임라인**. 처치 사건 → 해당 경기의 결말 → 조회로 확인 가능한 후속 기록. 위에 상대 식별 정보와 마지막 확인 시각.

- 공개 경기 기록 확인과 실제 실시간 위치 추적을 혼동시키지 않는다. 레이더·실시간 초록 점·지도 이동을 꾸며 넣지 않는다.
- 상대를 찾지 못함 / 이후 기록 없음 / 데이터 제공 범위 밖을 구별.
- 이후 사망·순위 등 서버에 있는 결과만 표시. 데이터가 없는 시간대는 추정하지 않는다.
- 스크롤이 긴 원수 목록은 간결한 행. 선택한 한 사람의 사건을 상세 열람.
- 기존 사이트의 자격증·사망진단서 외부 서브도메인 링크는 마이그레이션 시 동일 서비스 route 사용 여부 검토. 기능 확인 없이 일괄 변경 금지.

## 7. 루미아 신용정보원 `/credit/`

### 현행 입력 보존

닉네임 조회. 실험체별 평가, Thin File, 연체 이력. 현재 화면의 조회 이력 기록 안내는 실제 동작 여부 확인 후 유지하며 임의로 과장하지 않는다.

### 접수와 결과

대사: “그 실험체, 또 하려고? …기록부터 보고 결정해.”
결과는 **실험체별 신용대장 + 선택 실험체 평가서**.

- 상단에 조회 대상 닉네임과 데이터 범위. 목록 각 행은 실험체 초상·이름·등급·표본 상태.
- 등급순/실험체순 전환은 클라이언트 정렬로 처리. 등급 체계는 기존 데이터 순서 사용.
- 클릭하면 한 실험체의 평가서, 등급 근거, 연체 기록이 열림.
- Thin File은 낮은 신용등급이 아니라 표본 부족으로 별도 표현. 숫자 0점이나 F등급처럼 보이지 않게 한다.
- 재무 금융서비스를 연상시키는 실명/주민번호/실제 신용조회 동의 절차 추가 금지. 게임 닉네임만 사용.
- 저장은 개별 실험체 평가서 단위로. 전체 대장은 인쇄 페이지 분할 고려.

## 8. 루미아 노동청 `/payroll/`

### 현행 입력 보존

닉네임, 최근 랭크 10·20·30판, 예시 보기. 현재 지급·입장 공제·기타 조정·실제 RP 증감 계산과 데이터 누락 정책을 그대로 보존.

### 결과

대사: “이만큼 했는데 오히려 깎였다고? …명세서 뽑아줄게.”
중앙은 **급여명세서**, 옆/아래에 시급 한 줄, 펼칠 수 있는 출퇴근 기록부.

- 최상단 실수령 RP. 그 아래 `지급 합계 − 입장 공제 + 기타 조정 = 실수령`을 표 행으로 읽을 수 있게 표시.
- 시급은 실제 플레이 시간 기반. 대기·매칭 시간 제외 설명 유지.
- 기간은 한국 시간, 실제 확인된 경기 수를 표시. 요청 20판/확인 13판을 혼동하지 않게 표시.
- 랭크 외 경기 제외. RP 누락은 정산 보류; 0으로 대체 금지.
- 관측 예시: 현행 공개 예시의 +379 −420 +0 = −41 RP, 2시간40분, 시급 −15.4 RP. 실제 유저 기록으로 표현하지 않는다.
- PNG 저장, 실제 결과 공유, 경기 기록 펼치기 유지. 예시 공유 불가 상태를 설명.
- 흑자/적자는 색 + 부호 + 명칭으로 표시. 흑자도 지나친 성공 축하 화면으로 바꾸지 않는다.

## 9. 상황판 제외 — 사용자 최종 지시

루미아섬 상황판은 제거 예정이며 이번 설계에서 완전히 제외한다. 로비, 전체 서류, 공통 내비, 푸터에 상황판·지도·준비 중 링크를 넣지 않는다. 별도 관측 도구로 재편입하지 않는다. 기존 `/map/`의 실제 삭제·서버 라우트 처리·리디렉션은 구현 시 현 프로젝트 배포 범위에 맞게 결정한다. 이 설계 전달 작업은 운영 소스를 삭제하지 않는다.

## 10. 개발 확인표

- 기존 계산/API/URL/양식/저장 기능 보존 여부를 기능별로 확인.
- 문서 registry를 60개로 확장한 테스트에서 검색/분류/6행 페이지/최근3개 정상 작동.
- 결과없음, 부분응답, 네트워크실패, 이미지실패, 매우 긴 닉네임 테스트.
- 360/768/1024/1440px에서 가로 넘침과 버튼 잘림 없음.
- 탭 키, Enter, Esc, 검색 초기화, 포커스 복원, aria-live의 대사 전체 읽기 확인.
- 감소된 모션, 전환 도중 연타, 로딩 중 뒤로 이동 시 이전 응답이 다른 문서를 덮어쓰지 않음.
- 글꼴·실험체 이미지 로딩이 끝난 후 PNG 저장. CORS 이미지 문제 확인. 수익/과실 금액과 하단 면책문구가 잘리지 않음.
- 인쇄/PDF는 밝은 문서와 어두운 글자. 공통 셸/캐릭터/버튼은 인쇄 제외.
- 별도 종량제/유료 API 도입은 하지 않는다. 기존 인프라/정책을 준수.

## 확인 범위

브라우저에서 현행 문서 6종의 초기 UI 및 노동청의 공개 가상 예시를 확인했다. 실제 플레이어 닉네임으로 조회하거나 발급하지 않았다. 결과의 상세 필드는 원격 소스 확인 결과를 추가 자료로 연결하며, 구현 시 기존 응답 스키마를 최종 기준으로 삼는다.

## 11. 원격 현행 소스에서 확인한 결과 보존 항목

아래는 원격 프로젝트 소스 확인으로 보강한 필수 항목이다. 위 시각 설계를 적용하면서 삭제하거나 단순 요약으로 대체하지 않는다.

- **자격증:** 모드별 판수·승·승률·평균 딜량, 시즌별 판수·우승·승률·TOP3·평균 딜량. 일부 시즌 조회실패 수 명시. PNG/링크 공유.
- **사망진단서:** 사망 기록 재선택, 레벨·실험체·숙련 무기·사망 일시와 장소·순위, 사인 인과관계, 사망 종류, 처형자 사진·무기·활동·동기, 검시관 소견. 금지구역 등 비유저 원인 구별. PNG/PDF.
- **과실 산정:** 무사고 별도 상태, 사람별 약관 조항·벌점 횟수, 사고일지 행 펼치기(일시·모드·순위·RP·등급·과실·범인), 상세 딜량·K/A/D·생존·기권.
- **원수 관측:** 킬러 후보 선택, 타깃 레벨·시즌 참가·평균 킬·MMR, 해당 판의 처치 사슬, 이후 경기와 누적 MMR 그래프. 자연사 제외 문구.
- **신용정보:** 실험체·등급·점수·건수·승률·평균 순위·피조회 목록. 개별 등급·1000점 기준 점수·여신 판정/거래 조건·채무불이행 표시·평가 항목·연체 시즌 비교·거래 및 조회 이력. Thin File은 평가불가/보류/보증인 상태를 구별.

### 결과 설계 보정

사망진단서는 실제로 사망 기록 재선택을 제공하므로 문서 상단에 경기 선택을 유지한다. 원수 관측소는 처치 사슬과 이후 경기/MMR 추이를 각각 다른 영역으로 구분한다. 신용정보원의 점수는 기존 1000점 척도를 유지한다. 기능이 긴 상세는 근거 접기 영역으로 정돈하되 저장·공유나 도달 가능한 항목을 삭제하지 않는다.
